## BREAK 1 — EXPLOIT: remote-control village economy (REAL)

**Attack:** leave the haven (8 tiles out), call `Game.assignTask(vid,
'forage')` — default `in-person` via — and with `via: 'system-ping' /
'shout' / 'runner'`.

**Measured (pre-fix, seeded):** every call landed the assignment, no
refusal, no distance check, no ability check. `resolveAssignments` at the
part boundary then stocked **47,755 kcal** into the pantry for a drifter
standing 8 tiles away. The order also ran `socialTick` → `setEngaged(vid,
2)`, freezing the villager's batch behavior at your word from miles out.
The UI already knew the honest line ("You need to be face-to-face to ask
for help. (Abilities can unlock remote assignment.)") — the engine just
never said it. No ability in the data grants `remoteAssign` today, so every
remote via was a lie the engine accepted.

**Fix (game.js, `assignTask`):** mirror the UI's contract in the engine —
non-`in-person` via requires the method in `remoteAssignMethods()` (the
ability data contract; nobody has one yet, so all remote vias refuse);
`in-person` requires `playerAtHaven()`. Both refuse with the UI's honest
line. No new functions; ontology untouched.

**Design note for Steve:** this closes the "manage the village from the
road" fantasy for good — presence is the price of leadership, which is
exactly what the drifter archetype is supposed to sacrifice. When a real
remoteAssign ability ships (Shout/Runner/System Ping), it plugs into the
existing data contract and the gate opens for exactly that method.

## BREAK 2 — SOFTLOCK/CRASH: fresh-game starvation killed endDay (REAL)

**Attack:** none needed — the old proof suite tripped it. `D6b` (starving
village while away) threw `Cannot set properties of undefined (setting
'gen_…')` on seed 999.

**Root cause:** `villagerMealDay`'s starvation branch writes
`v.health[vid]` but nothing initializes `v.health` on a fresh game. The
04:30 suite only survived because `villageLives`' wounded branch happened
to init the map first on the old RNG sequence — village placement RNG
shifted since (village_0 moved (5,1)→(0,0) at seed 7), the wounded branch
didn't fire, and the first starving endDay crashed. On a real phone: a new
player whose village starves on day 1-2 hits this.

**Fix (game.js, `villageEats`):** `v.health = v.health || {}` up front,
before the roster loop. One line; the famine block's later init stays.

   death may land day 2-3. Contract under test is immediacy, not the day.
