### 🐛 Critical: the fix was applied to the wrong function

Commit `610a15f` ("fix talkTo dragging trust down to 40") modified `teachPlant`, not `talkTo`.

**Still broken** — `src/js/game.js` line 217, in `talkTo(vid)`:
```js
const newTrust = Math.min(40, trust + 3 * dipMult);
```
When `trust` is 71, `Math.min(40, 71 + 9)` = 40. Trust is dragged down.

**Was fixed** — `src/js/game.js` line 269, in `teachPlant`:
```js
this.state.village.trust[vid] = cur >= 40 ? cur : Math.min(40, cur + gain);
```

**Correct fix for `talkTo` (line 217):**
```js
const newTrust = trust >= 40 ? trust : Math.min(40, trust + 3 * dipMult);
```

**Repro:**
1. `giveFood(vid)` ×5 → NPC trust = 71
2. `talkTo(vid)` once → NPC trust = **40** (should stay 71)

## Phase 2: 30 playthroughs × 12 days

**Results:** 0/30 survived to day 12, 0 crashes, 0 negative kcal/HP violations.

**All 30 deaths were dehydration** (hydration → 0 → health drain → death at day 7-8). This is a **bot flaw, not a game bug**: the test bots did not seek water (no creek travel, no `doAction('treat')`). The game correctly models dehydration as lethal.

**What this confirms:**
- Death by dehydration works as designed (no crashes, no negative values, clean `over=true`)
- The survival pressure is real — water is not optional
- Bots need water-seeking logic for meaningful long-run survival stats (round 5's bots had this; round 6's simplified bots did not)

**Not a regression:** Round 5 reported 24/25 survival with water-seeking bots. The game logic is unchanged; only the bot was dumber.
